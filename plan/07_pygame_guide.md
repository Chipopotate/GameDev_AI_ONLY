# 07 — Гайд по pygame (как это делать)

Библиотека: **pygame-ce** (`pip install pygame-ce numpy`). Все примеры упрощены, адаптируй под структуру проекта.

## 1. Главный цикл и пауза
Фиксированный шаг симуляции, отрисовка отдельно:
```python
TICK = 1 / 60
acc = 0.0
paused = False
while running:
    dt = min(clock.tick(60) / 1000, 0.1)      # ограничить dt, чтобы не было скачков
    for e in pygame.event.get():
        handle_event(e)                        # пробел переключает paused
    if not paused:
        acc += dt
        while acc >= TICK:
            sim.update(TICK)
            acc -= TICK
    render.draw(screen, sim, camera)
    ui.draw(screen, sim)
    pygame.display.flip()
```
Пауза = просто не вызывать `sim.update`. UI и приказы работают как обычно. Приказы в паузе кладутся в очередь команд симуляции и применяются при снятии паузы.

## 2. Сетка и данные карты
Храни слои в `numpy`-массивах формы `(H, W)`: `terrain`, `building_id`, `infection`, `lit` (bool). Координаты тайлов целые, мировые координаты юнитов float в тайлах. Размер тайла в пикселях 🔧 `TILE = 24`.

## 3. Рисование примитивами
Всё рисуется кодом, без картинок. Базовые функции:
```python
pygame.draw.circle(surf, color, center, radius)
pygame.draw.rect(surf, color, rect, border_radius=3)
pygame.draw.polygon(surf, color, points)       # треугольники, ромбы, шестиугольники
pygame.draw.line(surf, color, a, b, width)
```
Правила:
- Один модуль `render/shapes.py` с функциями `draw_triangle(surf, color, pos, size, angle)`, `draw_diamond`, `draw_hexagon`, `draw_cross` и т.д. Все враги и здания используют их через поля `shape`, `color`, `size` из данных.
- Статичные вещи (тайлы земли) **не перерисовывай каждый кадр поэлементно**: рисуй карту в кэшированные куски-чанки (например, 16×16 тайлов на `Surface`) и обновляй чанк только при изменении.
- Рисуй только то, что в камере (отсечение по видимой области).
- Для плавных контуров цвета заранее вычисляй, не создавай `pygame.Color` в цикле.
- `Surface`, текст (`font.render`) создавай заранее и кэшируй. Не аллоцируй `Surface` каждый кадр.
- Для спрайтов с прозрачностью `convert_alpha()`, для фонов `convert()`.

## 4. Процедурные значки ресурсов (рандомизация внешнего вида)
Для каждого ресурса при генерации забега, используя `rng = random.Random(seed)`:
- **Название:** 2–3 слога из списка («кра», «зель», «мо», «ти», «ор», «вин»...), с заглавной буквы.
- **Цвет:** из HSV (`pygame.Color` + `.hsva`), случайный оттенок, насыщенность 60–90.
- **Форма:** выбор из `круг, ромб, шестиугольник, треугольник, кластер из 3 малых кристаллов, звезда`.
- Результат сразу рисуется на маленький `Surface` 24×24 и **кэшируется** по id ресурса. Рендер просто блитит кэш.
- Иконки 6 свойств **не** рандомизируются: у каждого свой постоянный цвет и форма (🔥 оранжевый треугольник, ⚡ жёлтая молния-ломаная, 🪨 серый квадрат, 💥 красная звезда, ✨ белый ромб, ⚙️ циановая шестерня-круг с зубцами).

## 5. Свет и тьма
- Освещённость хранится как `lit: np.ndarray[bool]` и пересчитывается **только** при изменении ламп.
- Расчёт круга: для каждой лампы маска по расстоянию (векторно в numpy в границах радиуса).
- Рендер тьмы: небольшой `Surface` размером с видимую область в тайлах (1 пиксель на тайл) с альфой 0–200, затем `pygame.transform.smoothscale` на экран. Получается мягкий край бесплатно и быстро.
- Тёмные тайлы скрывают врагов и здания частично (рисуй затемнение поверх, не выбрасывай сущности из симуляции).

## 6. Карта потока (пути врагов)
Одна из ключевых систем. Не считай путь для каждого врага отдельно.
- Стоимость тайла: свободный = 1, стена/здание = `wall_cost` (зависит от HP, например `10 + hp/10`), гора/вода = бесконечность (для наземных).
- Для типа врага считай **мультиисточниковый Dijkstra (`heapq`) от целей**, где стартовая стоимость цели = `BASE - priority * K` (чем выше приоритет цели, тем «ближе» она кажется). Каждый тайл получает направление к лучшей цели, а враг просто шагает по градиенту.
- Пересчитывай только при **изменении застройки** (флаг `dirty`) и не чаще 2–5 раз в секунду.
- Один флоу-филд на тип врага (а не на каждого). Летающие идут напрямую к цели без поля.
- Для карты ≤ 128×128 чистый Python + `heapq` достаточен. Если не хватает, вынеси цикл в numpy или уменьши частоту пересчёта.

## 7. Поиск целей и коллизии
- **Spatial hash** (словарь «ячейка → список юнитов») для поиска ближайшего врага/цели в радиусе. Не перебирай все пары.
- Коллизии между врагами не нужны (проходят друг сквозь друга) или простое мягкое отталкивание. Не делай физику.
- Снаряды: простые объекты с позицией, скоростью и уроном, проверка попадания через spatial hash.

## 8. Данные, а не классы
Враги, модули, корпуса, здания, рецепты описываются `dataclass`/dict в `data/`. Один класс `Enemy` с `type: EnemyType`. Особые способности через небольшие функции-хуки по `special`. Это упрощает добавление новых врагов из `05_enemies.md`.

## 9. Камера и ввод
- Камера: смещение `(cam_x, cam_y)` и масштаб (🔧 колёсиком, 0.5–2). Преобразования `world_to_screen` и `screen_to_world`.
- Управление дроном: WASD, мышь: выбор/приказы. Пробел: пауза. 1–9: группы роботов. F1/F2/F3: отладка.
- Выделение рамкой, приказы правой кнопкой, очередь по Shift.

## 10. Интерфейс
Свои простые функции, без UI-фреймворков: `draw_button`, `draw_panel`, `draw_bar` (полоса HP/патронов), `draw_tooltip`. Окна: инвентарь, книга рецептов, мастерская (выбор корпуса и модулей), HUD (день/ночь, % освещённости, энергия), экран поражения с причиной.

🔧 К M3.5 сделаны `ui/widgets.py` (`draw_panel`, `draw_text`, `draw_button`,
`draw_bar`, `draw_tooltip`, цвета — в `render/palette.py`), `ui/recipe_book.py` и
`ui/item_window.py` (инвентарь дрона и слоты лаборатории, сетка слотов — `ui/slot_grid.py`).
Все окна рисуются «немедленным режимом»: раскладка считается чистой функцией от состояния
симуляции в каждом кадре, прямоугольники между кадрами не хранятся, поэтому клик и
отрисовка всегда видят одну и ту же геометрию. Пока окно открыто, оно первым получает
клики (`Game._handle_click`) и блокирует добычу/скан в мире (`Game.poll_input`).

## 11. Отладочные оверлеи (сделай сразу, сэкономит время)
- F1: показать флоу-филд (стрелки или тепловая карта стоимости).
- F2: показать слой света/заражения.
- F3: FPS, число врагов, время пересчёта поля.

## 12. Тесты (без окна)
```
SDL_VIDEODRIVER=dummy python -m pytest -q
```
Обязательные тесты симуляции:
- генератор забега даёт проходимый граф рецептов для 1000 seed (`02_resources_recipes.md`);
- свет пересчитывается правильно после постройки/сноса лампы;
- враг выбирает путь с минимумом стен при наличии обхода;
- пауза: при `paused=True` состояние симуляции не меняется.

## 13. Частые ошибки (избегай)
- `random` глобально в симуляции (нужен `Random(seed)` явно).
- Создание `Surface`/шрифта каждый кадр.
- Перерисовка всей карты каждый кадр.
- Пересчёт путей каждый кадр или для каждого врага.
- Смешивание логики и `pygame` в `sim/`.
- Хардкод чисел баланса вне `config.py`/`data/`.
