# CLAUDE.md — инструкции для ИИ-агента

Проект: 2D рогалик + автоматизация + защита базы на **pygame-ce** (рабочее название «Свет»).
Автор говорит по-русски: общайся с ним по-русски. Код и идентификаторы — по-английски, комментарии можно по-русски.

**Проектные документы лежат в `plan/`** (нумерация `00`…`10`). Это источник правды по дизайну.
Ссылки вида `docs/01` внутри документов означают файлы в `plan/`.

## Как работать

1. Прочитай `plan/00_overview.md`, затем только те документы, которые нужны текущему этапу из `plan/08_roadmap.md`. Не читай всё подряд.
2. Работай **одним этапом за раз**. Этап готов, когда выполнены его критерии приёмки и тесты проходят.
3. Не добавляй механик, которых нет в документах. Если нужна новая система, предложи её автору текстом и жди ответа.
4. Пункты со статусом ❓ (открытый вопрос) не решай сам: спроси автора или реализуй самый простой вариант за флагом в `config.py` и сообщи об этом.
5. Пункты 💡 не реализуй без явной просьбы.
6. Когда решение меняется, обнови соответствующий документ в `plan/` и добавь строку в `plan/00_overview.md` → Changelog.

Статусы: ✅ решено, ❓ открыто, 💡 идея на будущее, 🔧 число для настройки (в `config.py`/`data/`, не хардкодить).

## Стек и правила

- Python 3.11+, `pygame-ce`, `numpy`, `pytest`. Больше зависимостей не добавлять без согласования.
- **Никаких внешних ассетов.** Вся графика рисуется примитивами (`pygame.draw`) и процедурно. Звука пока нет.
- **Симуляция отдельно от отрисовки.** `src/game/sim/` не импортирует `pygame` — это проверяется тестом
  `tests/test_architecture.py`. Рендер только читает состояние симуляции.
- Весь рандом через `random.Random(seed)`, передаваемый явно. Глобальный `random` в симуляции запрещён
  (тоже под тестом). Сид выбирает `app.py`, а не `sim/`.
- Числа баланса только в `src/game/config.py` и `data/*.py`. Типы врагов, модулей, зданий, рецептов
  описываются данными, а не отдельными классами на каждый тип.
- Простота важнее красоты: обычные классы и dataclass, без ECS и сложных паттернов.
- Производительность: не создавать `Surface`/шрифт каждый кадр (для этого есть кэши в `render/` и `ui/`),
  не перерисовывать карту целиком (кэш чанков), рисовать только видимое.

## Структура проекта

```
main.py                # точка входа + CLI (--seed, --screenshot, --bench, --headless)
plan/                  # проектные документы (00…10; 10_controls.md — управление)
src/game/
  config.py            # все числа баланса
  app.py               # окно, главный цикл, ввод, пауза
  data/                # описания: terrain, resources, recipes, relics, buildings (с рецептами построек)
  sim/                 # логика БЕЗ pygame
    world.py           # тайлы, генерация карты, залежи
    units.py           # дрон и drone.action (что он делает — для луча)
    resources.py       # Container, Hotbar, Cargo (правило «куда кладётся»), transfer
    simulation.py      # корень симуляции: update(dt), apply(команда), can_place
    commands.py        # команды UI → sim: SelectHotbar, PlaceBuilding, DismantleBuilding
    time_cycle.py      # день/ночь, события рассвета и заката
    light.py           # лампы и слой освещённости
    run_gen.py         # генератор забега, гарантия проходимости
    research.py        # знание о свойствах, plan_craft, KnownItems
    buildings.py       # работа зданий
    power.py           # сеть энергии
    drops.py           # предметы на земле
    # дальше по этапам: enemies.py, pathing.py, bases.py, bosses.py, meta.py
  render/              # отрисовка примитивами, камера, кэши
    ghost.py           # призрак постройки под курсором
    effects/laser.py   # луч дрона (красный/синий)
  ui/                  # HUD, отладочные оверлеи, виджеты
    state.py           # UiState: фокус ввода, text_input_active
    controls.py        # таблица управления (та же, что plan/10_controls.md)
    hotbar.py          # хотбар внизу экрана
    item_window.py     # окно E и окно здания
    craft_panel.py     # панель крафта в окне E: поиск, только изученное
tools/screenshot.py    # скриншоты сцен без окна (plan/09 § 12)
tests/                 # pytest, идут без окна
```

## Команды

На этой машине `python` в PATH — заглушка Microsoft Store. Используй `py`:

```
run_game.bat                     # запуск для автора: двойной клик, ставит зависимости сам
py -m pip install -r requirements.txt
py main.py                       # играть
py main.py --seed 42             # фиксированная карта
py -m pytest                     # тесты (608 шт., ~30 с)
py main.py --headless --bench 300       # замер производительности
py main.py --headless --screenshot screenshots/shot.png
```

Тесты без окна: `SDL_VIDEODRIVER=dummy` уже выставляется в `tests/conftest.py`.

## Управление

Единственный источник — **`plan/10_controls.md`** (та же таблица в `src/game/ui/controls.py`,
тест сверяет их построчно). Коротко: WASD — движение, ЛКМ держать — добыча / изучение реликвии /
разбор своей постройки, ПКМ — поставить постройку из слота хотбара или открыть окно здания, ПКМ
держать по залежи — скан, 1–9 — слот хотбара, R — поворот, E — инвентарь с крафтом, Пробел —
пауза, колесо — зум, F2/F3/F4 — слой света / отладка / галерея, Esc — снять фокус / закрыть окно /
выход. Мелкие правила там же, в «Уточнениях»: ПКМ по красному призраку или зданию без контейнеров —
ничего (без тоста); над хотбаром и панелями HUD нет призрака и действий в мир; нажатие, потраченное
на интерфейс или постановку, не становится удержанием; R с постройкой без направления в слоте
ничего не делает; пауза видна поверх окна.

## Определение «готово» для любой задачи

- Игра запускается без ошибок и держит 60 FPS на карте стандартного размера (F3).
- Тесты проходят. Для новой логики симуляции есть хотя бы один тест.
- Нет лишнего: не добавлено ничего вне задачи.
- Коротко отчитался автору: что сделано, что проверил, какие вопросы остались.

Отклонения от документов на текущий момент (подробнее в README.md):

- Стартовая зона замкнута горным кольцом (по `plan/01`), поэтому игрок из неё не выходит —
  обвал гор появится на M8. Свет снаружи кольца на «% освещено» не влияет: доступные тайлы
  считаются от точки старта.
- Свет дрона виден, но в счётчик «освещено» не входит (❓ в `plan/01` решён значением «нет»).
- Предметы на земле не исчезают по таймеру (`DROP_DESPAWN_SECONDS = None`).
- Рецепты предметов-построек (`data/buildings.py`) и скорости работы зданий — 🔧 догадки «чтобы
  работало»: балансировать их имеет смысл вместе с врагами (M5). `hp` и `enemy_priority` в данных
  уже есть, но не используются — ломать здания пока некому.
- ❓ В панели крафта «доступно» и «есть M» считаются по **открытым** свойствам (`KnownItems`), а сам
  крафт, как в M3, — по настоящим: приглушённый рецепт может скрафтиться. Вопрос автору в `plan/02`.
- ❓ Предметы ролей «Материал» и «Автоматика» сейчас никуда не тратятся (постройки крафтятся прямо
  из свойств); генератор открывается реликвией «Энергия», а не со старта. Оба вопроса — в `plan/02`.
- Разобранная постройка падает на землю предметом (не в инвентарь); предметы на земле под новым
  зданием остаются лежать. Клавиш T, I, Tab, книги рецептов (R) и 1–8 как режима стройки больше нет.
- R с лампой (постройкой без направления) в слоте не крутит и стоящий конвейер — буквально по
  дополнению к заданию M4.6 («если … призрака нет»). Сканирующей линии при стройке/сносе
  (`plan/09` § 10) нет: разбор — лёгкая вспышка, разрушение — осколки и тряска.
- Цена изучения реликвии оставлена ❓ за флагом `RELIC_STUDY_COST = None` (по умолчанию бесплатно,
  как в M3): в `plan/02` сказано «время/ресурс», но число не выбрано. Скан свойств при этом уже
  тратит 🔧 `SCAN_ENERGY_COST` = 2 энергии, а лаборатория требует сети.
